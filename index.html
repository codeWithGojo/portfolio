01 · About

My path into engineering started with hardware and embedded systems and has moved steadily up the stack into cloud infrastructure and DevOps. I like the layer where a physical sensor's reading becomes a decision a system — or a person — can act on.

03 · Approach

How I Work

01

Reliability first

A system that only works in the demo isn't finished. I design for the case where the network drops, the sensor lies, or the request times out — like the local buzzer failsafe in my fire detection system, which fires even without a connection.

02

Automate the boring part

If I'm doing it by hand twice, it becomes a script the third time. Automation isn't a nice-to-have on top of infrastructure — it's what makes infrastructure trustworthy at scale.

03

Instrument everything

You can't fix what you can't see. Monitoring and alerting go in from day one, not bolted on after something breaks — the same principle behind the push-alert loop my partner and I built into our own project.

05 · Projects

Featured Project

Final Year Project IoT + Cloud Full-Stack Built with a partner Successfully Defended

Smart Fire Detection & Alert System

Problem

Fire needs to be caught in seconds, not minutes — and someone away from the room still needs to know the moment it starts.

What We Built

An ESP32 rig (MQ-2 smoke/gas + DHT11 temp/humidity + buzzer) streaming live readings through a Flask API into Firebase, with a React Native app subscribed for real-time updates and FCM push alerts the instant a threshold is crossed. The buzzer fires locally even if the network drops.

Impact

Built, demonstrated, and successfully defended as a complete final year project — circuit to cloud to mobile app, working end to end.

ESP32 · MQ-2 · DHT11 · Flask · Firebase Realtime DB · React Native (Expo) · FCM
